# Публикация в Tilda: hosted calculator

Server-часть ступени C выполнена 2026-07-30 и обновлена 2026-07-31: `hosted/coffee-cost-calculator.html` из `main` commit `667281b` выложен на `https://api.barista-school.ru/api/coffee-cost-calculator.html` и проверен по HTTPS. Последняя правка увеличивает отступ между кнопкой «Изменить цены» и учебным пояснением до 32 px. Tilda-страница опубликована: 2026-07-31 публичный HTML подтвердил HTTP 200, один H1, статичный SEO-блок и loader.

## Что остаётся статичным в Tilda

- Единственный H1 и вводный текст страницы.
- Короткая SEO-статья, блок «Важно», FAQ и финальные CTA.
- SEO-настройки из `PROJECT_STATE.md`.
- Попап «Миксологии» с якорем `#consalt`.

Всё это уже собрано в `tilda-seo-block.html`: статья остаётся в исходном HTML страницы и не зависит от выполнения JavaScript поисковым роботом.

## Что вставлено в Tilda

В два HTML-блока Tilda вставляются файлы в строгом порядке:

1. `tilda-seo-block.html` — первым, выше калькулятора;
2. `tilda-loader.html` — вторым. Он автоматически переносит калькулятор в место между первым экраном и SEO-статьёй.

Не вставлять `tilda-block.html`: это полный локальный архив для preview. Не создавать видимый элемент с `id="consalt"` и не добавлять скрипт, который перехватывает этот якорь.

## Открытые Tilda-пункты

- Создать попап «Миксологии» с `data-tooltip-hook="#consalt"`: сейчас в публичном HTML найдена CTA-ссылка, но сам popup-hook отсутствует.
- Исправить поле Keywords: в опубликованное значение по ошибке попала служебная фраза «Вставь одной строкой…».
- После настройки вручную проверить `#consalt`, `/open_cafe_app` и интерфейс на 360 и 390 px.

## Как обновлять калькулятор после первой публикации

1. Изменить исходники в `src/`.
2. Выполнить `node scripts/build.mjs` и локальные проверки.
3. Независимо проверить `hosted/coffee-cost-calculator.html`.
4. Выложить только этот файл на сервер как `/var/www/html/api/coffee-cost-calculator.html` по утверждённому runbook.
5. Проверить публичный URL и страницу Tilda на мобильном устройстве.

Tilda после первой вставки loader не редактируется. Автодеплой из GitHub намеренно не входит в этот контур: каждая серверная выкладка остаётся отдельной проверяемой ступенью C.
